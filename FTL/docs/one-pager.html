FTL

0.7 (1) An iOS app that learns to read your receipts. Gmail in, a Google Sheet out, everything in between on the device.

The rule everything else follows

The model acts autonomously only where false positives are recoverable, and defers to tools where errors would be invisible. Everything canonical is gated by a rule or by you.

The boundary

System — deterministic

  • parse learned patterns + presets, executed with no model in them
  • dedup · pair fingerprint f(amount ±5.000, date ±3d)
  • every number CalcTool or a Sheets formula, never the model
  • memory tags and merchant names you already decided
Human gate

Agent — 2 jobs, both proposals

  • tag which bucket, for a merchant with no history
  • synthesize learn a sender's template, offline
  • never writes to the ledger, does arithmetic, or runs in the background
  • never routed on its own confidence

Where it stands

✓Sheets ledger — transactions + budgets, your own spreadsheet
✓The queue — correct the amount, merchant, bucket or kind, then approve
✓The loop — discover → synthesize → verify → promote, closing through the queue
✓Runs unattended — 4 triggers, all stopping at the cache
✓Widgets + notifications — daily reminder at a set hour, Shortcuts for an exact one

—Statement and photo rails — specified, not built

Known gaps — read before trusting a number

No test target. Five targets, none of them tests; every pure function here is verified by hand. No labels.json, so accuracy is measured against your agreement rather than ground truth — a rubber-stamped queue measures nothing. A 6.6 MB corpus still ships in the app bundle, ungated. IndonesianMoney is the only money parser: on a non-IDR mailbox the pipeline reads zero.
